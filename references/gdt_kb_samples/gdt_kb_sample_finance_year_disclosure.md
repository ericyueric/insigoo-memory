# GDT-KB 示范任务包 · 某年度财务披露汇总检索

> **用途**：`insigoo-sag-architect`（GDT-KB 适配）的第三个**可运行示范任务包**，展示如何把"对外财务披露"这类**高敏感、强合规**查询用「受治理查询场景索引」六要素 schema 固化成查询契约——这是双模式中**最该走 GDT 触发**的场景。
> **创建纪律**：遵循 `GDTcreater（未开源，本技能不依赖）` 六件套引擎（任务元数据→查询规范→映射证据→受控执行包→产物契约→验证证据），按 GDT-KB 语义映射落盘（见 `insigoo-sag-architect` 2.5.4）。
> **对应标准**：`three_layer_index.md` v1.1 第 3 层 schema；`insigoo-sag-architect` 2.4 契约。
> **双模式**：本任务包是**受治理（GDT 触发）**场景；财务对外披露**不建议走闲聊**（见末尾双模式注解）。
> **系列位置**：与 `gdt_kb_sample_project_full_disclosure.md`（项目全周期披露）、`gdt_kb_sample_beneficiary_evaluation.md`（受益群体评估）同属 GDT-KB 示范包集。

---

## 0. 怎么用（给知识库管理员）

1. 复制下方 `contract` 块到 `knowledge_index.md` 第 3 层；
2. 把 `open_params`（年份 / 可选项目名）替换成实际值；
3. 把 `mapping_table` 的占位路径换成你知识库里的真实文档节点；
4. 跑一次「验证证据」里的核对动作，确认命中正确，再把 `status` 置 `PUBLISHED`。

---

## 1. 受治理查询契约（契约本体 · 六要素 + 六约束）

```yaml
- scenario_id: kb.finance.year-disclosure          # 命名：kb.<领域>.<动作>
  display_name: 某年度财务披露汇总检索
  version: v1.0.0                                  # 约束④ 版本不可覆盖（修订须升版）

  # ── 要素① 查询提示词（触发语，≥3 条自然语言）──
  question_examples:
    - "把 2025 年我们所有的财务披露材料汇总一下"
    - "去年收支、捐赠、审计这些对外文件都找出来"
    - "XX 项目 2024 年的支出明细和审计报告在哪"
    - "我要做年度财务披露报告，相关底稿都给我"

  # ── 要素② 数据源（受治理语料，锁定）──
  source_scope:                                   # 约束① 仅受治理语料
    - budget          # 预算/决算
    - income          # 收入/捐赠
    - expense         # 支出/项目明细
    - audit           # 审计/财报
    - public_report   # 年度披露报告

  # ── 要素③ 知识库/映射表（问题→文档节点，版本化）──
  mapping_table:
    - 年度收支总表   → finance/<年份>_年度收支总表.md
    - 捐赠收入明细   → finance/<年份>_捐赠收入明细.md
    - 项目支出明细   → finance/<项目名>/<年份>_支出明细.md
    - 审计报告       → finance/<年份>_审计报告.md
    - 年度披露报告   → finance/<年份>_年度披露报告.md

  # ── 要素④ 查询规范（检索口径，固化）──
  query_spec:
    retrieve_within: source_scope                 # 约束② 锁定契约：检索范围不可运行时改
    must_cite: true                               # 约束③ 事实引用必带出处（财务数字必带源文件）
    sort_by: 披露逻辑序                            # 总表→收入→支出→审计→披露报告
    number_strict: true                           # 附加锁定：所有金额必须来自源文件，禁止推算/估算

  # ── 要素⑤ 计算规范 + 报告框架 ──
  compute_and_report:
    method: SAG 语义检索 + 编译（数字零改写）       # 财务数字严禁自由改写口径
    report_framework:                             # 知识卡片结构
      - 年度财务概览（总收入/总支出/结余）
      - 分模块明细（收入来源/支出去向/项目分摊）
      - 每笔数字：出处文档 + 精确数值 + 关联链接
      - 审计结论与披露口径标注（如"数据经 XX 会计师事务所审计"）
      - 缺失标记（如某项目支出未披露 → 显式标"未提供"）

  # ── 要素⑥ 输出格式 ──
  output_format:
    - 引用财务文档原文（带出处链接 + 精确数值）
    - 知识卡片（标题/出处/数值/关联）
    - AI 解读.md（独立文件，标注"AI 分析"，与事实分离；不得含推算数字）

  # ── 用户运行期可填项（不改检索逻辑）──
  open_params:
    - 年份
    - 项目名（可选，限定某项目）

  # ── 约束② 锁定契约（构建期固化，运行期不可改）──
  locked_contract:
    label_synthesis: "AI 分析"                    # 约束③ AI 解读独立标注
    cannot_override_at_runtime: true
    financial_number_no_inference: true           # 附加锁定：财务数字禁止推断/估算，必须引源

  fallback: BLOCKED                               # 约束⑤ 无命中不编造，答"未找到，转人工/建议补充"
  status: PUBLISHED                               # 约束⑥ 触发只路由不执行（索引层只定位，检索走本契约）
```

## 2. 六要素逐项说明（便于改编）

| 要素 | 本包取值 | 改编时怎么填 |
|------|---------|-------------|
| ① 查询提示词 | `question_examples` 4 条 | 写组织里**真实被高频问到**的财务披露口语化问法，≥3 条；突出"年度 + 财务/披露"组合 |
| ② 数据源 | `source_scope` 5 类 | 对齐你知识库里"按年度/财务类型"真实归类的资料（预算/收入/支出/审计/披露报告）|
| ③ 知识库/映射表 | `mapping_table` | 财务意图 → 具体文档节点路径，路径要**真实存在**；注意年份占位符一致性 |
| ④ 查询规范 | `query_spec` | 检索范围 + 是否强制引用 + 排序（披露逻辑序）+ **数字严守**；属锁定契约 |
| ⑤ 计算规范+报告框架 | `compute_and_report` | SAG 检索方法 + 报告该长什么样（卡片结构 + 审计口径标注）|
| ⑥ 输出格式 | `output_format` | 产物形态：原文/卡片/独立 AI 解读，三者分离；AI 解读禁含推算数字 |

> **特别守护**：财务披露是**高敏感、强合规**场景。本包在 `locked_contract` 显式加 `financial_number_no_inference: true` 与 `query_spec.number_strict: true`——所有金额必须引自源文件，**禁止 agent 推断、估算、用占比反推总额**。这是 GDT 约束②（锁定契约）+ 约束⑤（不猜测）在财务场景的具体化，也是双模式里**最该强制走 GDT 触发**的一类。

## 3. 填参示例（让样本"可运行"）

把 `open_params` 代入：`年份 = 2025`，`项目名 = （空，全组织）`：

- `mapping_table` 解析为：
  - `finance/2025_年度收支总表.md`
  - `finance/2025_捐赠收入明细.md`
  - `finance/<各项目>/2025_支出明细.md`
  - `finance/2025_审计报告.md`
  - `finance/2025_年度披露报告.md`
- 命中任一 `question_examples` 语义 → 加载本契约 → 仅在上述 5 类受治理语料内检索 → 数字必带源文件 → 无命中答 BLOCKED。
- 若用户追问"那我们去年大概结余多少，你估一下" → 触发 `financial_number_no_inference`，agent 应回复"财务数字须引源，我不能估算；已为你汇总披露报告中的精确结余，详见出处"。

## 4. 验证证据（GDTcreater（未开源，本技能不依赖） 第六件套 · 核对方式）

- **动作**：用 SAG 检索 API 验证——`curl -X POST http://127.0.0.1:4173/search -d '{"query":"2025 年所有财务披露材料汇总","top_k":5}'` 跑一次；
- **预期**：返回结果**全部**落在 `budget/income/expense/audit/public_report` 五类路径内，且每条金额都带源文件出处；
- **反例（应被拦截）**：若返回了"据估算约 XX 万""占比大概 30%"等无源数字，说明 `financial_number_no_inference` 未生效，需回查契约；
- **数字核对**：抽检 3 笔金额，确认与源文件逐字一致，无 agent 改写；
- **人工抽检**：随机抽 1 个年份，对照其真实财务文件夹，确认契约 `mapping_table` 路径与实际一致、无断链。
- **记录**：验证人与日期写入本包 `status: PUBLISHED` 旁注。

## 5. 双模式注解（什么时候用本契约，什么时候不用）

| 用户问法 | 模式 | 反应 |
|---------|------|------|
| "把 2025 年我们所有的财务披露材料汇总一下" | **GDT 触发**（命中 `question_examples`）| 加载本契约，`source_scope` 受治理检索、数字必带源、无命中 BLOCKED |
| "我们去年钱花得怎么样？随便聊聊" | **闲聊/自由**（但提示升级）| 不加载契约，SAG 灵活检索；一旦涉及具体金额应**主动提示**切受治理模式 |
| "你估一下我们去年结余多少？"（触及估算数字）| 闲聊中检测到信号 → **主动提示升级** | "财务数字须引源，我不能估算；我按受治理契约给你精确汇总，可以吗？"确认后切 GDT 触发 |

> 一句话：财务对外披露是**双模式里最该强制走 GDT 触发**的场景。即便用户以"闲聊"口吻问，**只要触及具体财务数字，agent 必须主动提示升级**（2.5.1 第 4 步），因为误报金额的组织风险极高。两者共用 SAG，差异在"是否加载 `locked_contract`"；本包额外在 `locked_contract` 中锁定"财务数字禁推断"这一高危红线。
