## 1. 知识库架构一览

```
my-wiki/                          # 知识库源文件（你编辑这里）
├── knowledge_index.md            # 三层索引（核心入口）
├── projects/                     # 项目知识
├── org/                          # 组织内部文档
├── methods/                      # 方法论
├── cases/                       # 案例库
└── ...

SAG 服务（独立进程，默认 http://127.0.0.1:4173）
├── /ingest        # 摄入单篇文档（写入即索引）
├── /search        # 语义检索
└── /batch_ingest  # 批量摄入目录
```

**关键原则**：
- ✅ 你只编辑 `my-wiki/` 目录下的 `.md` 文件
- ✅ 每次编辑完文档后，运行 `/ingest`（或 `/batch_ingest`）让 SAG 重新索引
- ✅ 编辑后同步更新 `knowledge_index.md` 索引（三层索引，见 `three_layer_index.md`）
- ❌ 不要手动改向量库（由 SAG 服务自动维护）

## 2. 摄入新文档

### 2.1 放到哪里？

按内容类型选择目录：

| 内容类型 | 放哪个目录 | 示例 |
|----------|-----------|------|
| 项目相关 | `projects/项目名/` | `projects/社区回收/计划.md` |
| 会议纪要 | `org/meetings/` | `org/meetings/2026-06-25_月度例会.md` |
| 制度流程 | `org/policies/` | `org/policies/志愿者管理.md` |
| 方法论 | `methods/` | `methods/社区动员方法.md` |
| 案例总结 | `cases/` | `cases/2026-06-20_义诊活动总结.md` |
| 日常工作 | `daily/YYYY-MM/` | `daily/2026-06/2026-06-25.md` |

### 2.2 文件命名规范

- 用中文，简洁描述内容
- 包含日期（格式：`YYYY-MM-DD_主题.md`）
- 示例：`2026-06-25_社区活动总结.md`

### 2.3 文档格式

每个文档头部应包含元信息：

```markdown
# [文档标题]

> **创建**: YYYY-MM-DD | **更新**: YYYY-MM-DD
> **维护者**: [姓名/角色]
> **状态**: 草稿 / 正式 / 归档

---

[正文内容]
```

### 2.4 更新索引

新增文档后，必须在 `knowledge_index.md` 中登记：
1. 第1层（目录索引）：添加到对应类别
2. 第2层（主题索引）：如果是新主题，添加主题条目
3. 第3层（受治理查询场景索引）：如果涉及高频/披露/合规问题，按 `three_layer_index.md` v1.1 的受治理查询契约 schema 添加场景条目（含 `source_scope` / `locked_contract` / `fallback`），而非一行朴素映射

### 2.5 摄入到 SAG

```bash
# 单篇摄入
curl -X POST http://127.0.0.1:4173/ingest   -H "Content-Type: application/json"   -d '{"path":"my-wiki/projects/社区回收/计划.md"}'

# 批量摄入整个目录
curl -X POST http://127.0.0.1:4173/batch_ingest   -H "Content-Type: application/json"   -d '{"root":"my-wiki"}'
```

**预期**：返回已摄入文档数与被索引 chunk 数。

## 4. 检索知识库

### 4.1 语义检索（推荐）

```bash
curl -X POST http://127.0.0.1:4173/search   -H "Content-Type: application/json"   -d '{"query":"志愿者管理制度","top_k":5}'
```

**示例**：
```bash
curl -X POST http://127.0.0.1:4173/search -d '{"query":"上次社区活动怎么做的","top_k":3}'
curl -X POST http://127.0.0.1:4173/search -d '{"query":"项目进展","top_k":5}'
```

### 4.2 受治理检索（对外披露/合规口径）

对外的、合规敏感、需审计的检索，走双模式检索规范（见 4.5）的 GDT 触发模式，由 `locked_contract` 约束检索范围与引用。

```bash
curl -X POST http://127.0.0.1:4173/search   -H "Content-Type: application/json"   -d '{"query":"XX 项目对外披露口径","mode":"governed","scenario":"<场景id>"}'
```

### 4.3 理解搜索结果

SAG 返回结构化结果，典型字段：
- **score** 越高越好（0-1，>0.7 算很相关）
- **file** 告诉你这段内容来自哪个文档
- **content** 是 chunk 原文（可能不完整，只是片段）

### 4.4 如果搜索结果不理想

1. 换个问法（用同义词）
2. 检查 SAG 服务是否已摄入最新文档（重跑 `/ingest` 或 `/batch_ingest`）
3. 看 [第5章](#5-故障排查)

### 4.5 双模式检索规范（GDT 触发 vs 闲聊）

> v1.1 回灌（来源：insigoo-memory GDT 通用化）：知识库查询分两种入口，反应规则不同。详见 `three_layer_index.md` 第 3 层 §3.1。

**判定层**：用户问题先与 `knowledge_index.md` 第 3 层已发布场景的 `question_examples` 做语义匹配——
- **命中 → GDT 触发模式（受治理）**：必须按该场景的 `locked_contract` 执行：仅检索 `source_scope` 受治理语料、引用必带出处、无命中答 `BLOCKED` 不编造、输出符合 `output_format`。**对外披露/合规/敏感口径一律走此模式**。
- **未命中 → 闲聊/自由查询模式**：不加载契约，SAG 灵活检索、可综合创造、优先基于事实但不强制逐条引用；不得当作组织正式知识资产对外披露。
- **信号升级**：闲聊中若检测到「对外披露/合规/敏感数据/需审计」信号，主动提示升级到 GDT 触发模式（"这涉及对外披露口径，我按受治理查询契约保证准确，可以吗？"）。

| 维度 | 闲聊 / 自由查询 | GDT 触发（受治理） |
|------|----------------|-------------------|
| 加载 `locked_contract` | 否 | **是** |
| 检索范围 | SAG 全量（灵活） | 仅 `source_scope` |
| 引用 | 优先基于事实，不强制 | **必带出处** |
| 无命中 | 灵活回应 / 建议补充 | `fallback: BLOCKED`，不编造 |
| 产物 | 非正式、不审计 | 正式受治理、可审计 |

> 两者共用 SAG 检索引擎，差异只在"是否加载 `locked_contract`"。完整契约 schema 与示范包见 `references/gdt_kb_sample_project_full_disclosure.md`。

## 5. 故障排查

### 问题1：检索返回空 / 连接拒绝

**原因**：SAG 服务未启动或地址不对

**解决**：
1. 确认 SAG API 服务已启动（默认 `http://127.0.0.1:4173`）
2. 浏览器打开 `http://127.0.0.1:4173/health` 应有响应
3. 若未启动，按 `references/sag_api.md` 的部署说明启动服务

### 问题2：检索结果不准确 / 过时

**排查**：
1. 确认文档已摄入：重跑 `curl .../batch_ingest`
2. 检查 `knowledge_index.md` 第 3 层场景条目是否覆盖该问题

### 问题3：摄入报错

**解决**：确认文件路径在 `my-wiki/` 内，且为 `.md` 格式。

## 6. 统计与质量检查

### 6.1 查看知识库统计

```bash
curl http://127.0.0.1:4173/stats
```

### 6.2 什么时候需要重新摄入？

| 情况 | 操作 |
|------|------|
| 修改了文档内容 | 重新 `/ingest` 该篇（或 `/batch_ingest`） |
| 换了嵌入模型 | 全量 `/batch_ingest` |
| 只是日常修改文档 | 单篇 `/ingest` |

| 频率 | 动作 | 耗时 |
|------|------|------|

## 8. 常见问题 FAQ

### Q1：不小心删了源文件，怎么办？
**A**：从备份恢复源 `.md` 后重新 `/batch_ingest`。

### Q2：搜索很慢，正常吗？
**A**：正常。语义检索涉及向量计算，约 1-3 秒。如超 10 秒，检查 SAG 服务状态。

### Q3：可以手动改向量库吗？
**A**：❌ 不可以。向量库由 SAG 服务自动维护。

### Q4：单篇摄入和批量摄入有什么区别？
**A**：
- **单篇 `/ingest`**：只处理一篇，快
- **批量 `/batch_ingest`**：处理整个目录，慢但全
- **日常用单篇，结构大改才批量**

### Q5：SAG 服务占用资源很高，可以关掉吗？
**A**：可以关，但关掉后摄入和检索都用不了。建议不用时关，需要时再起。
