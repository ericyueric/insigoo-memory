> 关联：`insigoo-sag-architect` SKILL.md 2.2（GDT-Core 双层）、2.4（查询场景索引治理）、2.5（双模式反应）。

## 0. 核心命题

GDT（标准数据任务）原本为「产品数据库 AI 数据助手」而生，现升级为**场景无关的通用治理内核 GDT-Core**，承载两层、缺一不可：

- **要素结构层** —— 任务包"由什么组成"：六件套（查询提示词 / 数据源 / 知识库映射表 / 查询规范 / 计算规范+报告框架 / 输出格式）。
- **纪律约束层** —— 构建/运行时"不可违背的红线"：6 核心约束（受治理源 / 锁定契约 / 事实解读分离 / 版本不可覆盖 / 不猜测 / 触发只路由）。

> 仅抽象成"6 约束"漏掉正面骨架（要素结构层）；仅列"六件套"缺治理红线。通用化必须两层同时承载。

---

## 1. GDT-Core 要素结构（通用化六件套）

| # | 要素 | 知识库场景落点（GDT-KB） |
|---|------|------------------------|
| ① | 查询提示词 / 触发 | 知识查询场景自然语言问法（`question_examples`） |
| ② | 数据源 | SAG 受治理语料（公益项目-披露 7 类索引区，`source_scope`） |
| ③ | 知识库/映射表 | 问题 → 文档节点映射（`mapping_table`） |
| ④ | 查询规范 | 检索范围/口径（`query_spec`） |
| ⑤ | 计算规范+报告框架 | SAG 检索+编译+报告框架（`compute_and_report`） |
| ⑥ | 输出格式 | 知识产物形态（引用文档/卡片/报告，带出处，`output_format`） |
| 附 | 验证证据 | 质量护栏：核对方式、预期样例、失败回归 |

---

## 2. GDT-Core 纪律约束（6 核心约束）

| # | 约束 | 知识编译中的落地 |
|---|------|----------------|
| ① 受治理源 | 编译只基于已归集、带出处与可信度的原始文档；禁凭模型记忆补内容、禁未核验网络抓取 |
| ② 锁定契约 | 分类口径/命名/模板/产物结构构建期固化（`locked_contract`），运行期不可由模型随意改 |
| ③ 事实与解读分离 | 编译产物（事实）与 AI 归纳/解读分离归档；解读标"AI 分析"，不得把推测当原文事实 |
| ④ 版本不可覆盖 | 编译标准/模板一经发布不可覆盖，修订须升版并保留旧版 |
| ⑤ 不猜测 | 原文缺失/分类 ambiguous/出处不可考 → 标 `BLOCKED`/`待确认`，绝不编造 |
| ⑥ 触发只路由不执行 | 索引/触发条目只做路由（定位受治理语料），真正编译/检索走锁定契约，不得自由生成 |

## 3. 双适配（同一套内核，两套落地）

```
GDT-Core（通用治理内核：要素+纪律双层，场景无关）
   ├─ GDT-DB（数据任务适配）  ← GDTcreater（未开源，本技能不依赖）范畴：结构化产品库、SQL 视图、六件套
   └─ GDT-KB（知识任务适配）  ← 本技能范畴：非结构化知识库、语义检索、查询场景索引
```

- 所有权边界：`GDTcreater`（未开源，本技能不依赖）负责 GDT-DB（数据域）；本技能负责 GDT-KB。
- GDT-Core 是共享契约：无论 DB 还是 KB，要素结构与纪律约束一视同仁。

## 4. 双模式反应模型（闲聊 vs GDT 触发）

现实：很多组织查询自由灵活，并非每问都该被受治理契约管死。第 3 层索引须区分两种入口，agent 反应规则不同。

**判定层（Trigger Decision）**：提取意图 → 与已发布 scenario 的 `question_examples` 语义匹配 → 命中即 GDT 触发模式，否则闲聊/自由查询模式；闲聊中检测到「对外披露/合规/敏感/需审计」信号 → 主动提示升级到 GDT 触发模式。

| 维度 | 闲聊 / 自由查询 | GDT 触发（受治理） |
|------|---------------|-------------------|
| 加载 `locked_contract` | 否 | 是 |
| 检索范围 | SAG 全量（灵活） | 仅 `source_scope` 受治理语料 |
| 引用要求 | 优先 grounded，不强制 | 必带出处（`must_cite`） |
| AI 解读 | 自由综合 | 独立标「AI 分析」 |
| 无命中 | 灵活回应/建议补充 | `fallback: BLOCKED`，不编造 |
| 产物性质 | 非正式、不写索引、不审计 | 正式受治理产物 |
| 对外披露 | 不得当正式知识资产 | 合规、可审计 |
| 口径漂移 | 允许 | 禁止（锁定契约） |

> 两者共用 SAG 检索引擎，差异只在"是否加载 `locked_contract`"。

## 5. 受治理查询场景索引（契约 schema）

每个高频查询场景从"问题→路径"朴素表升级为一份受治理契约（详见 SKILL.md 2.4）。核心字段：`scenario_id`、`question_examples`、`source_scope`、`mapping_table`、`query_spec`（含 `must_cite`）、`compute_and_report`、`output_format`、`open_params`、`locked_contract`（含 `version`）、`fallback: BLOCKED`、`status`。六要素一一对应索引落点，六约束一一守护索引纪律。

> 触发 ≠ 执行：索引层只做"问题 → 受治理语料"路由，绝不自行生成答案；真正检索/综合走 `locked_contract`。
